# Claude Code ↔ Telegram

Мост между Telegram и живущим на сервере Claude Code: пишешь в чат — попадаешь в
одну непрерывную сессию `claude` с полным доступом к машине. Голосовые
расшифровываются, файлы складываются в `uploads/`, ответ приходит с разбором
действий, токенами и ценой.

Отличие от «ещё одной обёртки над API»: бот умеет **править собственный код**.
Он вносит изменения, прогоняет проверки, коммитит и перезапускается; снаружи за
этим следит сторож, который вернёт прошлую версию, если новая не ожила.

## Быстрый старт

На чистой машине (Debian/Ubuntu, python 3.10+, желательно root):

```bash
git clone git@github.com:dytarasov/claudetelegram.git /root/tgassistant
cd /root/tgassistant
sudo make install
```

`make install` делает всё сам: venv и зависимости, ставит PostgreSQL с pgvector,
заводит базу и вписывает `DATABASE_DSN` в `.env`, разворачивает systemd-службу.
Останется вписать только две вещи, о которых он же и попросит:

1. **токен бота** от [@BotFather](https://t.me/BotFather) → в `.env`
   (`TELEGRAM_BOT_TOKEN=...`);
2. **свой Telegram id** для белого списка — подскажет `scripts/whoami.py`
   (просто напиши боту, и он поймает автора). Без списка бот не стартует: у него
   полные права на машине.

После этого повтори `sudo make install` — служба поднимется, и можно писать боту.

Перед запуском нужен установленный и авторизованный `claude` CLI:

```bash
curl -fsSL https://claude.ai/install.sh | bash && claude
```

Полезные команды (`make help` — весь список):

```bash
make test        # прогнать тесты
make run         # запустить вручную, без systemd
make db          # только провижининг БД (sudo)
```

Тонкая настройка — через `.env` (образец со всеми полями в `.env.example`).
Внешние ключи (Groq, OpenRouter) необязательны: без них работают локальное
распознавание голоса и полнотекстовый поиск по памяти.

## Как это разложено

```
src/
  bot.py                    тонкая прослойка: на неё указывает systemd-юнит
  app/
    settings.py             всё, что читается из .env (pydantic-settings)
    di.py                   dishka: где интерфейс встречается с реализацией
    main.py                 порядок запуска и ничего больше
    cli.py                  выкатка из терминала: deploy / rollback / preflight
    domain/                 модели, DTO, порты, ошибки — без единого импорта извне
    services/               логика: разговор, самодопил, здоровье, память
    infrastructure/         Postgres, git, systemd, процесс claude, Telegram, STT
    presentation/           роутеры aiogram и защита доступа
scripts/install.sh          установка на чистую машину (её зовёт make install)
scripts/setup_db.sh         провижининг Postgres + pgvector, запись DSN в .env
scripts/guard.sh            сторож: живёт вне процесса бота
tests/                      юнит-тесты на заглушках, без сети и БД
```

Зависимости направлены только внутрь: `presentation → services → domain`, а
`infrastructure` подключается к портам домена через контейнер. Поэтому сервис
можно проверить, подсунув ему словарь вместо Postgres, — что тесты и делают.

## Самодопил

```
правка → preflight → коммит → сторож перезапускает → пульс → выдержка → stable
                                       └─ не ожил ─→ git reset --hard → прошлая версия
```

* **preflight** — компиляция, импорт всех модулей, проверка настроек и `pytest`.
  Не прошло — не коммитится ничего, человек даже не замечает.
* **сторож** (`scripts/guard.sh`) запускается через `systemd-run` **отдельным
  юнитом**. Это обязательное условие: `systemctl restart claude-tg` убивает весь
  cgroup сервиса, и сторож внутри него умер бы вместе с ботом.
* **пульс** — `run/heartbeat.json`, обновляется раз в 5 секунд. Здоровым
  считается процесс, который дошёл до конца инициализации, видит Telegram и
  держит живой процесс claude. Просто «запустился» не считается.
* **версии** — коммиты. `stable` = «сюда возвращаться», `bad/<дата>` = «здесь
  сломалось, но сохранено», `rolled/<дата>` = «отсюда ушли по команде».
* сторож не знает ни про venv, ни про Postgres: только git, systemctl, curl и
  системный python3. Он обязан работать, когда не работает ничего другого.

Выкатка из терминала (или `make deploy NOTE='...' CHAT=<id>`):

```bash
venv/bin/python src/app/cli.py preflight
venv/bin/python src/app/cli.py deploy --note "что сделано" --chat <id>
venv/bin/python src/app/cli.py rollback stable
```

Коммиты самодопила подписываются нейтральным автором `claude-selfupdate`. Хочешь
свою подпись — задай `GIT_AUTHOR_NAME` и `GIT_AUTHOR_EMAIL` в `Environment=`
systemd-юнита.

## Команды в чате

| | |
|---|---|
| `/status`, `/ctx`, `/compact` | состояние сессии и контекста |
| `/stop`, `/new`, `/restart`, `/cd`, `/model` | управление сессией |
| `/get <путь>` | прислать файл с сервера |
| `/versions`, `/rollback`, `/stable`, `/diag` | самодопил и здоровье |
| `/recall`, `/note`, `/notes`, `/stats` | память: поиск по истории и заметки |

Плюс инлайн-кнопки: `/menu` — корневое меню, «Прервать» прямо на «живом»
сообщении хода, «Отмена очереди» на уведомлении о заторе.

## Хранилище

PostgreSQL с `pgvector` (локально, только `127.0.0.1`). Таблицы: `deployments` —
история выкаток и их исход, `turns` — журнал ходов с полнотекстовым поиском,
`notes` — заметки, `kv` — состояние между перезапусками (дублируется в
`state.json`, чтобы разговор пережил недоступность базы), плюс таблицы памяти.

Поиск по журналу гибридный: полнотекст Postgres находит точные слова и редкие
термины, вектор — смысл. Результаты сливаются ранговой фузией, потому что
абсолютные оценки двух методов несопоставимы, а места в списках — вполне.
Векторы считает `baai/bge-m3` через OpenRouter, колонки `vector(1024)`,
индекс HNSW по косинусной мере. Без ключа всё вырождается в полнотекст.

Миграции лежат в `src/app/infrastructure/db/migrations/*.sql` и накатываются
сами при старте. Правило: только вперёд и только совместимо — откат кода не
откатывает базу, поэтому новая миграция не имеет права сломать старую версию.
